One request, five boundaries

Every utterance follows the same path, whether it originated in the microphone or the text field. Only step 03 belongs to the VLM; everything else is deterministic Python.

01 / INPUT

Capture

Parakeet transcript, typed question, and optional dropped images.

02 / CONTEXT

Inject state

Python assembles the current graph, focused step, recent object reference, and pending fetch.

03 / VLM

Infer intent

Qwen returns one strict JSON envelope—never a direct robot command.

VLM decides this
04 / POLICY

Validate & decide

Python verifies schema, readiness, inventory, ambiguity, and graspability.

Python decides this
05 / EFFECT

Respond

Speak, highlight, select a step, request confirmation, or command a fetch.

Model judgment stops here

The architecture deliberately separates semantic interpretation from actions that mutate task or physical state.

VLM · probabilistic

Understands the operator

  • Classifies the utterance
  • Resolves names and pronouns
  • Returns ambiguity candidates
  • Drafts general answers
  • Uses visual context when provided
VALIDATION GATE
PYTHON · deterministic

Owns the consequences

  • Checks graph prerequisites
  • Tracks supplied and consumed parts
  • Maps semantic labels to tool IDs
  • Requires one unique graspable object
  • Requests confirmation before motion

Safety and consistency

Four mechanisms keep delayed or imperfect model output from becoming stale physical behavior.

⌁

Strict envelope

Unknown intents, invalid actions, or out-of-ontology labels are rejected.

1

Single-flight queue

Only one inference runs at a time; overlapping requests are declined.

↻

Versioned context

If graph state changes mid-inference, the old result is discarded as stale.

✓

Confirmation gate

A valid fetch request highlights first. “Yes” is required before robot dispatch.
